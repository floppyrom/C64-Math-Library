# Issue #39 — V1 Balanced exact 24÷8 fast path

**Date:** 2026-10-11. **Status:** source-backed V1 improvement; unsigned DIV/MOD *family* campaign remains open.

## Problem and implementation

The previous V1 UDIV24/UMOD24 Repose-based shared engine has a serious narrow-divisor tail. The earlier guarded V1-to-32/16 delegate saved time for some D8 operands, but did not efficiently handle the whole 24-bit dividend domain. In PR #60, widening that delegate was independently rejected because it produced regressions as high as +422 cycles.

Instead the shared V1 entry now dispatches to a **84-byte 24÷8 exact binary long-divider** for precisely N2>0, D2=D1=0, D0>0, after the existing early cases. The engine shifts the unmodified input's copied numerator bits through the public MATH_Q destination over 24 iterations; the partial remainder lives in MATH_R+0. Its ROL carry is the ninth remainder bit. Each successful subtraction sets the next quotient bit in MATH_Q+0. R1 and R2 are cleared before a CLC return. This uses **zero additional normal-ZP bytes, no stack, no changed input bytes or public addresses**, and has deterministic 24 iterations.

The new source island is **REG_LOW+$0D00–$0D53** (reference $1D00–$1D53), inside previously unused resident space. V1 retains its existing D1!=0 fallback with identical instruction timing. The existing N2=0 early cases, zero divisor, and other high-divisor classes bypass the new code completely. The prior routine's $7FA0 dispatch changes; resident PRG length stays the same.

**V5:** Both 24-bit public entries already use its faster V2-derived imported core. In the V5 hybrid builder, the new V1-only REG_LOW+$0D00–$0D7F donor range is verified, then reclaimed before V5's independently selected 32/32 narrow-divisor helper is installed. Its V1 inherited unused old selector bytes are restored symbolically. **V5's reference resident binary remains byte-for-byte unchanged**, not merely cycle-equivalent. The V5 alternate build also passes.

The new permanent audit reconstructs the exact previously published V1 parent resident from the new binary and verifies its SHA256 is `97c3e04112335e5958653ac656771b9e11d1d4fede0f5c824b9169aa49b1b564`. It compares **56,580 complete old/new CPU calls** across canonical and seven supplementary workloads, plus large D8, wide-divisor, and N2=0 controls. It checks carry, remainder, quotient for UDIV, N/D preservation (including byte +3), and rejects **even a single slower call**. Recorded largest saving on full-width D8 stress: **893 cycles**.

Additionally, V1 full-profile 164,410 unsigned calls and reference/alternate symbolic assembly passed. A native full-resident VICE x64sc proof checked 80 calls per image (160 total), both public API entries, against old/new output equality and independent Python quotient/remainder/carry oracle. The saved emulator executable identifies as VICE 3.10 despite the ZIP label mentioning 3.13.2.

The existing negative selector-expansion audit from PR #60 is preserved by reconstructing its old V1 parent, rather than testing a counterfactual patch against the new V1 gate. Its archived rejection JSON remains unchanged.
