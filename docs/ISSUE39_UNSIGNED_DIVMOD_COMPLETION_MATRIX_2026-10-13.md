## Why the 32÷16 general-path audit remains necessary

The resident path computes the high 16-bit quotient/remainder using the existing 16/16 producer, then extends into a low-word continuation. Front-end narrow-dividend delegation can be fast when callers **already know** their operands satisfy the helper's preconditions. Published five-profile tests show that attempting to recognize these cases inside every unrestricted call incurs an ordinary full-width dispatch cost. That is a legitimate workload tradeoff, not a default promotion.

The remaining manual synthesis should therefore begin inside the source-owned continuation—reuse carry and register state, simplify successful/failed subtraction transitions and inspect branch-page phase—before adding another unconditional public-entry discriminator. This is a **research direction**, not a measured performance claim.

## Required reproducible closure gates

1. Freeze `RELEASE_STATUS.json` resident SHA pins, public API addresses, official same-input corpus and at least the six 32÷16 workload strata. Check both `UDIV` and `UMOD` aliases, especially V1's quotient side effects.
2. Reassemble any proposed instruction/architecture changes at both reference and alternate maps; for V5 regenerate the hybrid from the actual donor sources. Reject hidden extra ZP, stack or table dependencies.
3. Compare *paired* old/new instruction-cycle vectors on identical operands, including faster/slower counts and worst regressions. Keep REU DMA/bus costs distinct from CPU-only instruction timing.
4. Validate divide-by-zero carry, quotient/remainder, retained N/D, sentinel bytes, input/output ownership, mixed calls, illegal opcode semantics and any ROM-underlay or RAM-execution preconditions.
5. Screen compatible OptiSearch ideas under the library's real public/ABI/resource envelopes and perform a manual post-OptiSearch synthesis pass. Keep private OptiSearch internals out of the public repository.
6. For an actual production change: full five-profile and relocated source builds, deterministic unsigned/signed public test suites, native VICE for affected entries, package/standalone audits, updated performance tables, both changelogs, release status and checksum ledger, then independent PR and post-merge `main` CI.
7. If credible compatible architecture candidates are exhausted with no improvement worth integrating, publish a **bounded, reproducible no-gain decision**, specifying exactly what was screened. Do not claim mathematical global optimality.
