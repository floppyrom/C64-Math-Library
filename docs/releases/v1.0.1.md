# C64 Math Library v1.0.1 — Maintenance Release

This is a maintenance update to the first operation-first C64 Math Library release. **v1.0.0 stays available and unchanged.** v1.0.1 corrects documented Make entrypoints and legacy source-validation/compatibility tooling; it does **not** reintroduce the historical fixed installation profiles.

## Fixes since v1.0.0

- **Clean-checkout frame builder:** `make builder-frame` now generates the supplied, source-qualified math-only example evidence when the standard output path is used. Custom missing reports fail explicitly rather than fabricating measurements (PR #397).
- **Legacy validation:** `make legacy-validate` now performs real, passing validation of today's V1–V5 source implementations: assembly, relocation, source repeatability, signed arithmetic, hybrid and Pareto checks (PR #399).
- **Historical donor correctness:** repaired comparisons with current source-built donors, UMUL8/UMUL24/SMUL24 legacy Pareto source relocation and complete-core copying, physical resource accounting, and page-phase preservation.
- **Regression coverage:** new real Make-command CI tests for the operation-first builder, interactive setup, weighted-speed build, clean frame example, current-source legacy validation, and package inventory.

## Upgrade

For new projects, use the same operation-first workflow as v1.0.0:

```sh
make builder-setup
```

Or build a saved configuration with `make builder CONFIG=path/to/config.json`. Generated `math_selective.prg`, `math_api.inc` and `selective_manifest.json` remain matched project-specific outputs; there is no universal bundled binary.

To validate a fresh source checkout:

```sh
make builder-validate
make legacy-validate
make builder-frame
make package-audit
```

For byte-for-byte frozen resident verification, `make legacy-frozen-verify` is **separate and currently expected to fail** for V1–V4 as tracked in [issue #398](https://github.com/floppyrom/C64-Math-Library/issues/398). A successful `make legacy-validate` does not assert historical frozen PRG identity.

## Scope and limitations

- The same 56 independently linkable stock-C64 public operations and four selection objectives (balanced, speed, size and ZP) remain available.
- Turbo16, Turbo32 and QS16 are separate, explicit REU-side-memory/DMA companion services, not mandatory or universal speedups.
- The library is not reentrant. Actual mixed IRQ/VIC/SID/REU application deadlines and sustained 25/50 Hz behavior depend on the user's program and are not certified by the math-only frame example.
- 1541/1571/1581 operation-first execution backends are **not** included. Full fastest historical source parity remains tracked separately in [issue #375](https://github.com/floppyrom/C64-Math-Library/issues/375).

**Release integrity:** the v1.0.1 workflow validates the exact release commit: all 56 catalog entries, operation-first setup regression, optional REU setup, builder and frame smoke tests, current-source legacy tests, and source-package SHA-256 integrity. It creates a new immutable v1.0.1 tag/release and never moves or replaces v1.0.0.
