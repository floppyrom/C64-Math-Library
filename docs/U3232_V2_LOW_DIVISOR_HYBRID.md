# Experimental unrestricted full-width 32/32 DIV/MOD hybrid

**Research status:** independent source qualification; not selected by the
operation-first builder and not part of the V1–V5 production profiles.

## Algorithm

A new entry named `FAST_UDIV32_32_HYBRID` (also exported as
`FAST_UMOD32_32_HYBRID`) checks the upper two divisor bytes:

- **D fits in 16 bits:** call the canonical V2 Pareto-Fast **public-ABI**
  32-by-16 quotient/remainder producer, including its 12 ZP staging bytes.
  Preserve its quotient, carry and low 16-bit remainder; explicitly write
  zero to the upper 16 bits of the public 32-bit remainder. D=0 continues to
  return Q=0, R=0, C=1.
- **D requires 32 bits:** tail-jump to the existing, independently
  qualified four-ZP `FAST_UDIV32_PUBLIC` divider that returns full Q32/R32.
  Both donor implementations preserve N32 and D32 public inputs.

This retains an **unrestricted 32-bit public divisor**, unlike a bounded
specialist that merely assumes an 8- or 16-bit divisor. The two public
operation names intentionally share one Q/R-producing function.

## Code layout and ownership

Both canonical donor sources are assembled independently and relocated by
`tools/selective_hybrid_u3232.py`. Code and gaps occupy exactly **3,200
bytes** in a NOP-padded, caller-owned RAM image. A shared 12-byte ZP range
covers both non-reentrant donor workspaces; no additional private RAM scratch,
tables, stack-page execution, REU or self-modifying code are introduced by
the wrapper. The public I/O interface still reserves 32 bytes separately.

At code base `$8000` the layout is:

| Component | Offset | Source |
|---|---:|---|
| Historical fast 32/16 main and tail | `$000C` / `$0500` | `pareto_udiv32_16.a` |
| 32/16 public adapter | `$0900` | generated by validated V2 emitter |
| Unrestricted 32/32 core/tail | `$0A00` | `div_u32_zptail.asm` |
| Width dispatcher and both exports | `$0C40` | generated by hybrid emitter |
| End of reserved image | `$0C80` | 3,200 bytes total |

The second qualified map places code at `$7123`, moves the 32-byte I/O
window to `$C040` and the shared ZP base to `$70`.

## Reproduce CPU-model and native correctness

```sh
python3 tools/test_selective_hybrid_u3232.py
# In GitHub Actions, with VICE_WRAPPER pointing to a real x64sc:
python3 tools/native_selective_hybrid_u3232.py
```

The CPU-model test compares each hybrid public Q32/R32/C call against the
existing independently qualified ZP-tail producer on **identical full32
operands**, including zero, narrow, unrestricted and high divisors.
It checks every output, carry, original public N/D input byte, caller SP and
all executable bytes at two relocations. The cycle comparison records both
low-divisor and wide-divisor subsets so a gain restricted to narrow divisors
is not misreported as a universal full32 speedup.

The native VICE gate independently executes both public aliases at both
memory maps and verifies complete full-width arithmetic and flags.

**Promotion is a separate decision:** only register this image as a
source-qualified builder variant if the CPU model and native x64sc gates pass,
the full ordinary input corpus improves meaningfully without a major p95 or
worst-case regression, and a 12-ZP/3,232-main-RAM Pareto tradeoff is worthwhile.
No resident binaries, published production cycle records or profile
defaults are altered by this research source.
